# TT-023 — Release build & browser smoke: implementation

## Summary
`npm run smoke` builds the release file and drives it in the installed Chrome. It passes all 8 ticket checks and has passed 6 runs in a row, each taking 28–50 s.

**Build step**
- It runs `tools/build.js --release`.
- The `--release` flag already existed, so `build.js` is unchanged. The minified file is 462 027 bytes, under the 1.5 MB limit.
- The file is checked for `http`, `//cdn`, `<link` and `src=`; none are present.

**Browser runs**
- The driver is playwright-core 1.63.0, pinned exact as a dev dependency, using `executablePath: /usr/bin/google-chrome` (Chrome 150).
- Every context aborts and records any request that is not `file:`, `data:` or `blob:`.
- All input is real keyboard events. Hooks are only read, through `__tallyman` state.

**The five scenarios**
- **A. 390×844, full boot.** The boot stops at PRESS PLAY ON TAPE until a key, then runs tape → title → intro. The intro pages at `[MORE]` and a key continues. The run then plays to the wrong-man ending.
- **B. 1800×1100, `?skipboot=1`.** TYPEWRITER OFF, then all 91 STORY §12.1 commands typed in about 3 s. History is checked with ↑↑↓↓. The run ends on the victory screen: "THE TALLY SETTLED", "YOU SCORED 100 OF 100 IN 91 TURNS".
- **C. localStorage save and load.**
  - SAVE 1, reload, LOAD 1, then 3 commands. Their output and status line are identical to the reference run without the reload.
  - Then "read page" leaves its disambiguation question pending. SAVE 2, reload, LOAD 2 asks the question again, and the answer matches the reference.
- **D. `localStorage` throws** (an init script overrides the getter).
  - The notice appears exactly once per page load, and SAVE reports "session only".
  - EXPORT is captured as a download. After a reload, IMPORT goes through the real file chooser, and the continuation is identical.
- **E. After-ending save.** A save taken after the wrong-man ending is IMPORTed into a fresh page. The ending text and then the ending screen appear. LOOK says the game is over, UNDO says "can't undo", and RESTART returns to play.

Console errors, console **warnings** and page errors are all collected across every run: there are 0. The run writes the report `docs/SMOKE-REPORT.md` and six `docs/screenshots/release-*.png`.

## Decisions made
- **Smoke is kept out of `npm run check`**, so check stays fast and needs no Chrome.
- **Both builds write `dist/tallyman.html`.** Whichever ran last wins: smoke writes the minified release build, and check writes the unminified one.
- **The after-ending save comes from `__tallyman.game.save()`.** After an ending the engine accepts only UNDO, LOAD, RESTART and IMPORT, so SAVE and EXPORT cannot produce such a save from the UI. The restore itself goes through the real IMPORT and file chooser.
- **Disambiguation route.** The pending question uses the route from the save-determinism suite (`WALKTHROUGH[0..69]` + `read page`). SAVE is a barrier, so the question survives the save.
- **The walkthrough is imported from `tests/walkthrough/script.js`** (`WALKTHROUGH`), so the browser types exactly the list the Node suites check.
- **Typewriter off is set by typing `TYPEWRITER OFF`.** This is the real player path; no stored setting is injected.
- **The harness avoids typing stray spaces.** It presses Space only to page `[MORE]` or to skip typing that is still running after 150 ms, and erases input that is only spaces. Without this, a skip press landing just after the output finished was typed as a leading space. That is correct terminal behaviour, but it made runs flaky.
- **File-chooser listener from the start.** A `filechooser` listener is attached as each page opens, because Playwright enables chooser interception asynchronously; a late `waitForEvent` missed the chooser.
- **The report is generated by each run**, so it never goes stale. My visual notes are kept here instead.

## Known gaps / follow-ups
- At 390 px the game renders at scale 1, so its text is very small on a phone. This is TT-012's design and not a defect, but it is worth a look by eye on a real device.
- Audio is never heard in headless runs. Only the absence of errors is checked.
- When a skip key arrives just as the output ends, it is typed into the input as a space. This is correct per TT-011, and the engine trims it, but the echo then shows `>  cmd`. Trimming the echo would be a cosmetic follow-up.
